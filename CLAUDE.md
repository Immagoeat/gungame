# The Meridian: notes for Claude

(The game was called Gun Game; packages are still `@gungame/*`, saves use `gungame.*` storage keys, and the launcher is `gungame.sh`. Keep those as they are. "Gun Game" is now just the name of the weapon-ladder mode.)

See README.md for the layout and commands. Conventions:

- TypeScript everywhere, strict. Run `npm run check` (typecheck + tests) after changes.
- `packages/shared` must stay pure: no `three`, DOM or Node imports. Anything the server needs to simulate (physics, maps, weapon stats, protocol) goes here.
- Gameplay rules belong in a `GameMode` (`packages/client/src/modes/`), not in `Game`. `Game` is the engine and state machine.
- Tunable numbers live in data (`shared/src/weapons.ts`, `difficulty.ts`, `constants.ts`, `gungame.ts`), not inline in systems.
- Changing a type in `shared/src/protocol.ts` requires bumping `PROTOCOL_VERSION`.
- Tests sit next to the code as `*.test.ts` (Vitest). Prefer testing shared logic.
- Electron: VS Code terminals set `ELECTRON_RUN_AS_NODE=1`. Launch through `./gungame.sh` or `npm run dev:desktop`, which unset it.
- Node 18 is installed. Don't bump Vite, Vitest or Electron majors until Node is upgraded.
- Maps: author with `MapBuilder` in `shared/src/maps/`. Mansion conventions: +x east, -z north (back of house), floor tops at `MANSION_LEVELS`. Add a zone for every new room, and a walkthrough test when you change stairs or doors (see `mansion.test.ts`).
- In dev builds `window.game` is the Game instance (handy for teleporting: `game.player.pos.set(x, y, z)`).
- 3D model files live in `packages/client/public/models/` and load before `Game` is built (`assets/AssetLibrary.ts`). Anything that uses a model must keep working without it (procedural fallback). Record every new file's source and license in `models/CREDITS.md`. Geometry from model files is shared between copies: never dispose it.
- Character posing (`entities/character/rig.ts`) works in world space on Mixamo bone names, so it doesn't depend on a rig's local bone axes.
- The packaged app serves the client from `app://game/` (see `desktop/main.cjs`) because `fetch` doesn't work on `file://`. Rebuild (`npm run build`) after client changes; `gungame.sh` only builds when `dist` is missing.
- `Game.startMatch` is async (it loads behind the loading screen); don't `await` it from code that needs to keep running, and check `loadToken` after every await when extending it.
- New missions: give them a `loadingImage` (render one from the game at 1920x1080, save as JPEG under `public/images/loading/`) and, optionally, an `intro` cutscene.
- Mansion chapter rules live in `modes/campaign/mansionMission.ts`; guard perception and alarm tuning in `npc/GuardManager.ts`. Keep `NavGrid.test.ts` passing when moving guards, doors or the hostage (every route must be walkable).
- Spoken lines live in `client/src/audio/voicelines.json` (text = subtitle). After adding or editing one, re-render with `python3 tools/voice/generate.py --piper … --model …` (Piper + en_US-libritts-high; see `public/audio/CREDITS.md`); `voice.test.ts` fails until you do.
- Campaign balance numbers live in `DIFFICULTIES[...].stealth` (shared). When moving guards, cameras or entrances, check sight coverage: run `tools/balance/coverage.cjs` (dev server up; heat maps of how fast a crouched player is spotted). Keep `World.clearLine` grid-based (it rebuilds when colliders are added or removed).
- Chapter 2 (the Aurelia): ship decks are `AURELIA_DECKS`; keep stair holes free of floor coverings (`cover()` in aurelia.ts does it) and doors at least 1.2 m wide (the nav grid won't pass narrower ones). `aurelia.test.ts` must reach every room, guard post and pickup from the stateroom. Cover rules (which zones each outfit may enter) are in `modes/campaign/aurelia/cover.ts`, by zone name. The ship is closed in by invisible `barrier` blocks (`m.barrier`: they stop bodies, not bullets or sight): a skin round the hull, and strips over the edge rails and bulwark. Floor openings over stairs must reach the walls beside them (a lip catches your head), and `aurelia.test.ts` walks every flight and fuzzes random movement: run it after touching stairs, decks or rails.
- Movement (`physics/collision.ts`) only climbs a ledge if there's headroom on top, lands only on boxes it came down onto, and never pushes a body through to the far side of a box. Keep it that way: those were the stair teleports and wall clips. `trim` is non-solid (the wall behind it does the work).
- Lights: map lights (`m.light`, chandeliers) share a fixed pool of real point lights (`LightSystem`, POOL_SIZE), handed to the fixtures nearest the camera each frame; only shadow casters are always in the scene. Adding lamps is cheap; to brighten a whole map use `m.lightGain` / `m.lightReach` (the ship uses them).
- Footsteps are surface-aware: `World.surfaceAt` maps the floor's material to a sound (`SURFACE` in World.ts). Give new floor materials an entry there. Guards' footsteps are positional and muffled through walls.
- Ship props for crew spaces (`washer`, `storageRack`, `crewLocker`, `galleyRange`, `controlPanel`, `helm`, `radarConsole`, `pipeRun`) live in `furniture/ship.ts`.
- Chapter 3 (the Port, `shared/src/maps/port.ts`): flat yard at y = 0, the quay edge at `QUAY`, the fence at `FENCE`, Ops' upper floor at `OPS_UPPER`. Undercover missions share `modes/campaign/undercover.ts` (OutfitDef) and `modes/campaign/wardrobe.ts`; each mission's `cover.ts` maps zone names to access (the port's unnamed inside-the-fence areas fall back to staff-only). `port.test.ts` must reach Nadia, every lead, the charge spot and the van from the car park, keep the fence closed except at its gaps, and walk the Ops stairs. The compound must stay beatable unseen (two inner patrols, a lane camera, a 5 s plant: check with a scripted attempt after changing it), and `port.test.ts` checks the west-fence hole is the short way out. Restricted areas: `MissionHud.restricted()` (warning card + red edge) and `TacticalMap.restricted` (shaded zones) are driven by each undercover mission's cover rules; mark new restricted doorways in the world too (`warningSign`, `hatch()` in port.ts).
- NavGrid treats standable tops within `SAME_FLOOR` (15 cm) in one column as one floor (a covering on a slab); two layers there made guards' paths detour through doorways to switch layers.
